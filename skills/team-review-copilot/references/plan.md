# Plan Review Criteria

Use these criteria when the reviewed scope is an implementation plan, task list, or TODO document.

指摘には行番号ではなく、対象ステップの番号か見出しを添える。

## 観点

- **手順の抜け漏れ**: 各ステップの成果物が、次のステップの前提を満たしているか。前提を満たさないまま次に進むステップはどれか
- **依存関係の矛盾**: 後のステップの成果物を前のステップが必要としている箇所がないか。並列実行できると書かれたステップが同じファイル・同じリソースを触っていないか
- **ロールバック可否**: 各ステップに、失敗したとき元の状態に戻す手順が書かれているか。戻せないステップ（マイグレーション、外部への送信、削除）がどれで、それが計画のどの位置にあるか
- **検証ステップの有無**: 各フェーズの完了を、実行して確かめる手段（テスト、コマンド、確認画面）が書かれているか。「動作確認する」だけで何を見るか書かれていない箇所はどれか
- **未確定事項の扱い**: 決まっていない箇所が「未定」と明示されているか。決まっていないまま断定形で書かれた箇所はどれか

## Severity基準

| Severity | Action | 基準 |
|----------|--------|------|
| **CRITICAL** | Must fix | ロールバック不可能な破壊的操作を含み、失敗時に取り返しがつかない |
| **HIGH** | Must fix | 依存関係の矛盾や検証手段の欠如により、計画が途中で破綻しうる |
| **MEDIUM** | Consider | 手順の粒度が粗い、想定外ケースの考慮が薄い |
| **LOW** | Skip | 表現や順序の好みなど、実行可否に影響しない指摘 |
