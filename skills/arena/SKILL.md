# Arena

## 呼び出し元が渡すもの

- 課題: 単独で呼ばれたときは `$ARGUMENTS`
- 種類: 設計（各候補が設計案を文章で出す）か、実装（各候補がコードを書く）
- 意図（目的、完了条件、変えない範囲、仮定した業務ルール）。単独で呼ばれて無ければ、課題から 1〜2 文で書く
- run: 単独で呼ばれたときは HEAD の先頭 7 文字

## 役

| 役 | モデル | 動かし方 |
|---|---|---|
| 候補 Opus | Opus 5.5 medium | Agent ツールの subagent（`run_in_background: true`） |
| 候補 Astra | Codex `gpt-6.2-astra`、effort medium | その回だけのペイン `arena-astra` |
| 候補 Gemini | Antigravity `gemini-4-neon-high` | その回だけのペイン `arena-gemini` |
| 審査役 | Antigravity `gemini-4-neon-high` | ペイン `judge`（作業フォルダはリポジトリ） |
| 親 | このセッション | 課題と採点基準を決め、自分でも採点し、元にする候補を選んで移植する |

ペインの開き方、起動直後の処理、使い回し、待ち方、結果の読み方は、herdr-panes の SKILL.md（このファイルのフォルダから見て `../herdr-panes/SKILL.md`）に従う。

## 手順

1. 採点基準を決める。課題に固有の 3〜6 項目に、次を足す。採点基準は候補には渡さない。
   - 1 つの状態に持ち主が 1 つ
   - 1 つの作業にやり方が 1 つ
   - 呼び出す側が知るべきことが一番少ない
   - no-overengineering の SKILL.md（`../no-overengineering/SKILL.md`）の、「設計でも使う」が「使う」の観点に当たらない
2. 候補ごとの worktree を HEAD から作る。前の回の worktree が同じ場所に残っていたら（手順 7 からのやり直しなど）、`git worktree remove --force` で消してから作る。置き場所は `${TMPDIR}/arena/<リポジトリ名>/candidate-<a|b|c>`。どの候補にどの文字を当てたかは親だけが記録する。フォルダ名にモデル名を入れない（審査役に渡すパスからモデルが分かるため）。設計の arena でも作る（候補がコードを読むため）。
3. 3 体を同時に起動して、同じ依頼文を送る。依頼文には次を入れる。
   - 課題と意図
   - 作業フォルダ（その候補の worktree の絶対パス）
   - 「スキルは使わずに作業してください」
   - 「git の状態を変えるコマンド（commit、stash、checkout、reset、branch、rebase）は使わないでください」
   - 返答の形: 作ったものの説明と、検討して却下した案とその理由。ペインには「`=== RESULT ===` の行から書き始め、`=== END ===` の行で終えてください」、subagent には「結果は最後の返答にすべて書いてください。メッセージでは送らないでください」
4. 3 体の完了を待つ。何も出なかった候補は外して、残りで進める。
5. 審査役に、候補を A、B、C のラベルだけで渡す（どのモデルが書いたかは伝えない）。設計なら各候補の返答を、実装なら各 worktree のパスと `git -C <worktree> diff` を渡す。採点基準で項目ごとに採点し、元にする候補を推薦させる。ファイルは変更させない。
6. 親も全候補を最後まで読んで、採点基準で項目ごとに採点する。全体の印象では選ばない。審査役と推薦が一致すれば、その候補を元にする。割れたら、どちらかの採点が偏っているか採点基準があいまいだったとみなし、両方の理由を読み直して決める。点数が並んだら、境界がきれいなほう、API が小さいほうを選ぶ。
7. 元にした候補に、他の候補から取り入れる価値のある部分を、候補ごとに多くて 1〜2 個選んで移植する。無ければ取らない。移植するときは貼り付けず、元にした候補の作りに合うように書き直す。3 体の形がほぼ同じなら、移植せずにその形を使う。3 体の形が大きく割れたら、課題の書き方があいまいだったとみなし、案を混ぜて平均を取らずに、課題と採点基準を書き直して 1 からやり直す。
8. 実装の arena なら、結果を呼び出し元の作業ツリーに反映する。コミットは呼び出し元がする。
9. `arena-astra` と `arena-gemini` のペインを閉じ、候補の worktree を `git worktree remove --force` で消す。単独で呼ばれたときは `judge` のペインも閉じる。

## 返答

- 元にした候補と理由
- 審査役と親の採点（項目ごと）。割れた場合はどう決めたか
- 移植した部分と、元の候補
- 却下した案と理由（候補の返答と、親が移植しなかったもの）
- 脱落した候補と、3 体の形がそろったかどうか
- 設計の arena なら、決まった設計
