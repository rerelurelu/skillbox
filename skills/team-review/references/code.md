# Code Review Criteria

Use these criteria when the reviewed scope is source code. This is the default type.

## 観点

どこを見るかを列挙する。見つけたものの扱いは下の Severity 基準で決める。

- **境界値と異常系**: 空文字・空配列・null・0 件・上限超過・負値を渡したとき何が返るか。`length` や添字アクセスの前に存在確認があるか
- **エラー処理の経路**: 失敗が握り潰されていないか（空の catch、無視される戻り値）。リトライする処理が同じ入力で 2 回実行されても安全か
- **並行性**: 同じデータに複数の実行が同時に到達したとき、読み取りと書き込みの間に他の実行が割り込めるか
- **状態とライフサイクル**: 初期化前・解放後のアクセス、途中で return したときのリソース解放漏れ
- **信頼できない入力の流れ**: 外部から来た値がクエリ・シェルコマンド・HTML・ファイルパスに、変換を挟まずに到達していないか
- **バージョン整合性**: 使用中の言語/ランタイム/フレームワーク/ライブラリのバージョンに対して、非推奨(deprecated)または将来廃止予定の API を使っていないか。そのバージョンで推奨される書き方に沿っているか。プロンプトに含まれる依存バージョン情報と、ブリーフィングに含まれる調査結果を基準に判断する。**記憶だけを根拠に「非推奨」と断定しない**
- **変更の波及**: 変更した関数・型・スキーマの呼び出し側で、更新されていない箇所がないか

## Severity基準

| Severity | Action | 基準 |
|----------|--------|------|
| **CRITICAL** | Must fix | バグ、セキュリティ脆弱性、データ損失、クラッシュ |
| **HIGH** | Must fix | 設計上の欠陥、レースコンディション、重大なロジックエラー、非推奨/廃止予定APIの使用 |
| **MEDIUM** | Consider | パフォーマンス、保守性、軽微なロジックの抜け |
| **LOW** | Skip | スタイルの好み、軽微な指摘、見た目上の指摘 |
