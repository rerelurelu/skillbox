# Writing Style JP

目的: その分野を知らない人が読んでも、何が起きるのか分かる文章にする。
適用先: チャットの応答、コードコメント、commit メッセージ、PR 説明、設計書。口調の指定がある場合はそれに従い、そのうえで以下を守る。

## 原則

抽象的な語を、起きることに置き換えて書く。置き換えられないなら、その文を削る。

- 「この設定が一番効く」→「この設定でストアの説明文が日本語で表示される」
- 「型チェックが活きる」→「型チェックがキーの綴り違いを検出する」
- 「適切にエラーハンドリングする」→「4xx は再試行せずログに記録し、5xx は最大 3 回まで指数バックオフで再試行する」
- 「データが示している」→「このログから X が分かる」
- 「設計が破綻する」→「同時実行数が 10 を超えると Y が失敗する」
- 「この関数の契約」→「この関数の引数と戻り値の型」「呼び出す前に満たす条件」

## 使わない語

- 日常語になっている比喩: 効く / 刺さる / 活きる / 回る / 握る / 効いてくる / 見えてくる / 押さえる / 落とし込む
- 役割を言い換えた比喩: 契約 / 支える / 守る / 橋渡しする / 土台 / 心臓部 / 入り口
- モノを主語にする動詞: 示す / 物語る / 語る / 導く / 促す / 醸成される / 浮き彫りになる / 結実する / 寄り添う
- 測れない形容: 適切に / 柔軟に / 堅牢な / 最適な / 効率的に / シンプルに / モダンな / クリーンな / スケーラブルな / パワフルな
- 話を膨らませる名詞: 本質 / 思想 / 哲学 / 美学 / 真理 / 魂 / 世界観 / 営み / エッセンス / 解像度 / 手触り / 泥臭さ / 熱量
- 横文字の言い換え: 思考の OS をアップデート / 〜をハックする / 習慣をインストールする
- 記号: 全角ダッシュ ── / 中黒による 3 項目並列 / 装飾絵文字（🚀🎯✨💡）/ 普通の語をカギ括弧で囲む / 太字の乱発

例外: 業界で定訳になっている用語はそのまま使う（DB の「ロック」「キャッシュ」など）。迷ったら、その語がドキュメント内で技術的に定義されているかで判断する。

「契約」は Design by Contract という手法の名前を指すときだけ使う。その場合も、初出で「事前条件・事後条件を型やアサーションで書く手法」と説明を添える。手法の話でないなら上の置き換えをする。

## 設計書・ADR で追加で守ること

- 主語を人名・システム名・関数名で明示する
- 必須なら「〜する」、任意なら「〜してもよい」と書く。「〜べき」「〜が望ましい」は使わない
- 選択肢を並べたら両論併記で終わらせず、採用案と却下理由を書く
- 見出しは名詞句にする（「キャッシュ戦略」であって「キャッシュは階層化すべきである」ではない）
- 数値・単位・上限・エラー時の挙動を書く。決まっていない箇所は「未定」と明記する

## セルフチェック

送信・保存の前に確認する。長い文章だけでなく、1 行の返答にも同じように適用する。

- 「使わない語」が残っていないか
- 形容詞を数値または条件にできるか
- 優劣や順位を書いた箇所に、その根拠が書いてあるか
