# Infra Domain Criteria

Additive criteria for scope containing infrastructure code (IaC, CI/CD, container/orchestration config). Use alongside the type criteria (`references/<type>.md`), not in place of them.

## 観点

- **最小権限**: ワイルドカード（`*`）を含む権限指定がないか。付与された権限のうち、実際に使われていないものはどれか。CI に付与したトークンの権限範囲が、そのジョブがやることを超えていないか
- **シークレット管理**: 認証情報・トークン・秘密鍵がリポジトリ内のファイルに直接書かれていないか。環境変数・シークレットマネージャ経由になっているか。ログやエラー出力にシークレットが混ざる経路がないか
- **冪等性**: 同じ適用を 2 回実行したとき、2 回目で何が起きるか。CI を再実行したときに、既に作成済みのリソースで失敗しないか
- **ロールバック・影響範囲**: 変更を戻す手順があるか。この変更が失敗したとき、停止するのはどのサービスの、どの範囲か
- **可観測性**: 変更後もログの出力先・メトリクスの収集・アラートの発火条件が維持されるか。監視対象のリソース名やラベルを変更していないか
- **ネットワーク露出**: `0.0.0.0/0` からの受信を許可している箇所がないか。公開する必要のないポート・エンドポイントが開いていないか
- **バージョン固定**: ベースイメージ・Action・プロバイダのバージョンが可変タグ（`latest`、メジャータグのみ）で指定されていないか

## Severityの当てはめ

type 側の Severity 表に当てはめる。判断が割れる観点は以下に寄せる。

| 観点 | 当てはめ先 |
|------|-----------|
| シークレットのハードコード、ログへの流出 | CRITICAL（セキュリティ脆弱性） |
| `0.0.0.0/0` 開放、不要なポート公開 | CRITICAL（セキュリティ脆弱性） |
| ロールバック手順のない破壊的変更 | CRITICAL（データ損失） |
| ワイルドカード権限、過剰な権限付与 | HIGH |
| 冪等でない適用（再実行で失敗する） | HIGH |
| 可視性の欠落、バージョン未固定 | MEDIUM |
