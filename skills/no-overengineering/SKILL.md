# No overengineering

実装役が書くときに守る規則。設計と arena の採点にも使う。実装のあとは overbuild-arbiter がこの観点で差分を裁く。各観点は「当たる」と言える根拠を持つ。根拠を示せないものは観点に当たらない。

## 観点

ID は `OE-` に番号を付けた固定の ID で、ほかのスキルから ID で参照する。観点を消しても番号を詰めず、消した番号は使い回さない。新しい観点には、このファイルで今までに使った一番大きい番号の次を使う。コメントとドキュメントの観点は no-comments にあり、ID は `CM-` で始まる。

| ID | 観点 | 当たると言える根拠 | 設計でも使う |
|---|---|---|---|
| OE-1 | 認識合わせの完了条件と仮定した業務ルールに無いケースを扱っている | 完了条件にも仮定にも無く、今の呼び出し元や入力からそのケースが起きない | 使う |
| OE-2 | 将来のための拡張（使われない引数、オプション、差し込み口） | 今の呼び出し元のどれも使っていない | 使う |
| OE-3 | 実装が 1 つしか無いインターフェースや抽象化、作るものが 1 種類しか無い factory | 実装が 1 つしか無い | 使う |
| OE-4 | 受け取ったものを渡すだけで、呼び出し元が 1 つしか無いラッパーや層 | 呼び出し元が 1 つしか無く、中で値を変えたり判断したりしていない | 使う |
| OE-5 | 変わらない値を設定にしている | 値が 1 つしか使われず、上書きする場所も無い | 使う |
| OE-6 | 同じことをする手段が 2 つある | 2 つの手段の場所 | 使う |
| OE-7 | 1 つの状態に持ち主が複数いる、ほかの値から計算できる値を状態として持っている | 計算元か、もう 1 つの持ち主の場所 | 使う |
| OE-8 | リポジトリに既にあるものを作り直している | 既存のコードの場所 | 使う |
| OE-9 | 標準ライブラリ、プラットフォームの機能、導入済みの依存で済むものを自前で書いている。またはそのために依存を足している | 置き換え先の機能名 | 使う |
| OE-10 | 内部で起こらない入力への防御、同じ検証の繰り返し | 型か呼び出し元がその入力を来ないと保証している | |
| OE-11 | 例外を握りつぶすだけのエラー処理、ログを出すだけで何もしない catch | 握りつぶしている場所と、そのあとの挙動 | |
| OE-15 | 同じリポジトリの周りのコードと違うやり方で書いている | 同じことをしている既存のコードの場所 | 使う |
| OE-16 | 型の誤りを避けるためだけのキャスト（`any`、`as`、unchecked cast など） | キャストの場所と、避けている型の誤り | |
| OE-22 | 消した機能や挙動が無いことを確かめるテスト | そのテストと、消した機能 | |

## 当てはめないもの

次のものは観点に当たるように見えても消さない、直さない。

- 外から入ってくるデータの検証（ユーザー入力、外部 API の応答、設定ファイル、環境変数）、データの消失を防ぐエラー処理、セキュリティのための処理、アクセシビリティの基本
- 完了条件や依頼文で明示的に求められたもの、テストと検証のためのコード（OE-22 に当たるものを除く）

## 指摘の書き方

レビューや採点で観点に当たるものを挙げるときは、次を書く。

- 場所（`file:line`）
- 観点の ID
- 根拠（表の「当たると言える根拠」の列で求める事実）

直し方は書かず、直す側に任せる。

## 範囲

呼び出し元が差分の範囲を渡す。単独で呼ばれたときは `$ARGUMENTS` のコミットから HEAD まで。`$ARGUMENTS` が無ければ、`main` から分かれた地点から HEAD まで。

## 手順

1. Agent ツールで `subagent_type: "relubox:overbuild-arbiter"`、`run_in_background: true` の subagent を起動し、次を渡す。
   - 意図（目的、完了条件、変えない範囲、仮定した業務ルール）。単独で呼ばれて意図が無ければ、コミットメッセージから 1〜2 文で書く
   - 設計（決めたデータの形と選んだ案）。呼び出し元に無ければ渡さない
   - 作業フォルダの絶対パス
   - 差分の範囲
   - このファイルの絶対パス
   - 前の回で捨てた指摘と理由。前の回が無ければ渡さない
2. 結果を点検する。次の指摘は捨てる。
   - 「当てはめないもの」に当たる
   - 差分の範囲の外のコードを指している
   - 根拠が書いていない、または根拠の事実を確かめると違う
   - コメントやドキュメントを指している
   - 前の回で捨てた指摘と同じ前提のまま挙げ直している

   直すと変えない範囲を壊す指摘と、呼び出し元がユーザーと合意した設計を変える指摘は、直さずに分けて返す。
3. 残った指摘を直す。直し方は直す側が決める。
   - qstack から呼ばれたとき: 指摘の一覧を qstack に返す。直し方は qstack の playbook で決め、直すのは qstack の実装役
   - 単独で呼ばれたとき: 根拠を読んで、観点に当たらなくなるように自分でコードを直す。直し方が何通りも考えられて割れるときは、arena を種類「実装」で回す。直したら、プロジェクトの lint、typecheck、関連するテストを実行する

## 返答

- qstack から呼ばれたとき: 受け入れた指摘の一覧（場所、観点の ID、根拠）、変えない範囲または合意した設計に当たるので直さない指摘、捨てた指摘と理由
- 単独で呼ばれたとき: 指摘ごとの直し方、実行した lint、typecheck、テストの結果、変えない範囲に当たるので直さなかった指摘、捨てた指摘と理由
