# Interrogate

## 範囲と意図

- 範囲: 呼び出し元が差分の範囲を渡す。単独で呼ばれたときは `$ARGUMENTS` のコミットから HEAD まで。`$ARGUMENTS` が無ければ、`main` から分かれた地点から HEAD まで
- 意図: 呼び出し元が認識合わせ（目的、完了条件、変えない範囲、仮定した業務ルール）を渡す。単独で呼ばれたときは、依頼文とコミットメッセージから書き、分からなければユーザーに聞く
- run: 呼び出し元が渡す。単独で呼ばれたときは HEAD の先頭 7 文字

## 攻撃役

| 役 | モデル | 動かし方 |
|---|---|---|
| Opus | Opus 5.5 medium | Agent ツールの subagent（`run_in_background: true`） |
| Astra | Codex `gpt-6.2-astra`、effort medium | ペイン `attack-astra` |
| Gemini | Antigravity `gemini-4-neon-high` | ペイン `attack-gemini` |

ペインの開き方、起動直後の処理、使い回し、待ち方、結果の読み方は、herdr-panes の SKILL.md（このファイルのフォルダから見て `../herdr-panes/SKILL.md`）に従う。

## 手順

1. 攻撃役ごとの worktree を HEAD から用意する。置き場所は `${TMPDIR}/interrogate/<リポジトリ名>/<役>`。すでにあれば `git -C <worktree> checkout --detach HEAD のコミット` で合わせる。無ければ `git worktree add --detach <path> <コミット>` で作る。
2. 3 体に同じ依頼文を送る。ペインの作業フォルダはそれぞれの worktree。

```
あなたはこの変更を壊す役です。スキルは使わずに作業してください。

## 意図
<目的、完了条件、変えない範囲、仮定した業務ルール>

## 対象
作業フォルダ: <この役の worktree の絶対パス>
変更: git diff <開始のコミット>..HEAD

## やること
この変更が意図を満たさない場合を探してください。完了条件を満たさない、変えない範囲を壊す、仮定した業務ルールと違う動きをする、のどれかです。

## 指摘の条件
- 指摘はすべて、実際に実行して示してください。失敗するテスト、再現スクリプト、間違った出力を出すコマンドなどです
- 試す入力や再現スクリプトは作業フォルダの中か一時ディレクトリに作ってください。作業フォルダの既存のファイルは変更しないでください
- git の状態を変えるコマンド（commit、stash、checkout、reset、branch、rebase）は使わないでください。この作業フォルダは worktree で、stash やブランチをほかの作業ツリーと共有しています
- 実行していないものは書かないでください。スタイル、命名、構造、将来の変更で初めて問題になるリスクも含みます
- 指摘なしも正当な結果です

## 返答
（ペインの場合）=== RESULT === の行から書き始め、=== END === の行で終えてください。
（subagent の場合）結果は最後の返答にすべて書いてください。メッセージでは送らないでください。
指摘ごとに: 題名、実行したコマンド、出てきた出力、意図が求める出力
```

3. 3 体の完了を待つ。
4. 指摘ごとに、そのコマンドを指摘した役の worktree で実行し直す。失敗が出て、しかも意図を壊しているものだけ残す。原因が同じ指摘はまとめる。
5. 捨てた指摘は攻撃役ごとに件数と理由（再現しなかった、意図を壊していない、実行の証拠が無い など）を記録する。
6. 仮定した業務ルールそのものに関わる指摘（仮定が違うのではないか）は、確かめた指摘とは分けて返す。
7. 単独で呼ばれたときは、ペインを閉じて（herdr-panes の「後片付け」）、worktree を `git worktree remove --force` で消す。qstack から呼ばれたときは、qstack の報告のあとに qstack が片付ける。

## 返答

- 意図
- 確かめた指摘: 指摘ごとに、コマンド、出力、意図をどう壊すか、見つけた攻撃役
- 仮定した業務ルールに関わる指摘
- 捨てた指摘: 攻撃役ごとの件数と理由

修正はしない。
