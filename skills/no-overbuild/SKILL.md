# No overbuild

実装役が書くときに守る規則。設計と arena の採点にも使う。各観点は「当たる」と言える根拠を持つ。根拠を示せないものは観点に当たらない。

## 観点

番号は観点の固定の ID で、ほかのスキルから番号で参照する。観点を消しても番号を詰めず、消した番号は使い回さない。新しい観点には、今までで一番大きい番号の次を使う。

| # | 観点 | 当たると言える根拠 | 設計でも使う |
|---|---|---|---|
| 1 | 認識合わせの完了条件と仮定した業務ルールに無いケースを扱っている | 完了条件にも仮定にも無く、今の呼び出し元や入力からそのケースが起きない | 使う |
| 2 | 将来のための拡張（使われない引数、オプション、差し込み口） | 今の呼び出し元のどれも使っていない | 使う |
| 3 | 実装が 1 つしか無いインターフェースや抽象化、作るものが 1 種類しか無い factory | 実装が 1 つしか無い | 使う |
| 4 | 受け取ったものを渡すだけで、呼び出し元が 1 つしか無いラッパーや層 | 呼び出し元が 1 つしか無く、中で値を変えたり判断したりしていない | 使う |
| 5 | 変わらない値を設定にしている | 値が 1 つしか使われず、上書きする場所も無い | 使う |
| 6 | 同じことをする手段が 2 つある | 2 つの手段の場所 | 使う |
| 7 | 1 つの状態に持ち主が複数いる、ほかの値から計算できる値を状態として持っている | 計算元か、もう 1 つの持ち主の場所 | 使う |
| 8 | リポジトリに既にあるものを作り直している | 既存のコードの場所 | |
| 9 | 標準ライブラリ、プラットフォームの機能、導入済みの依存で済むものを自前で書いている。またはそのために依存を足している | 置き換え先の機能名 | 使う |
| 10 | 内部で起こらない入力への防御、同じ検証の繰り返し | 型か呼び出し元が、その入力を来ないと保証している | |
| 11 | 例外を握りつぶすだけのエラー処理、ログを出すだけで何もしない catch | 握りつぶしている場所と、そのあとの挙動 | |
| 12 | コードの動きをなぞるだけのコメント、コメントアウトされたコード | そのコメントとコード | |
| 13 | 自分たちのコードの分かりにくさを説明しているコメント | 説明が要らなくなる直し方（名前を変える、切り出す、型で表す、設計を変える） | |
| 14 | 変更の外にあるコメントやドキュメントが、変更前の内容のまま残っている | 変えた名前や挙動の検索結果と、古い記述の場所 | |
| 15 | 同じリポジトリの周りのコードと違うやり方で書いている | 同じことをしている既存のコードの場所 | |
| 16 | 型の誤りを避けるためだけのキャスト（`any`、`as`、unchecked cast など） | キャストの場所と、避けている型の誤り | |
| 17 | 正しさ、バグ、安全性を捕まえる lint や型チェックのルールを抑制している（`eslint-disable`、`@ts-ignore`、`@ts-expect-error` など） | 抑制しているルールの名前と、そのルールが防ぐ誤り | |

## 当てはめないもの

次のものは観点に当たるように見えても消さない、直さない。

- 外から入ってくるデータの検証（ユーザー入力、外部 API の応答、設定ファイル、環境変数）
- データの消失を防ぐエラー処理
- セキュリティのための処理
- アクセシビリティの基本
- 完了条件や依頼文で明示的に求められたもの
- テストと検証のためのコード
- コメントのうち、次のもの
  - ライセンスのヘッダー
  - 自分たちでは変えられない外部の事情（依存ライブラリ、プラットフォーム、ベンダー、プロトコル）による挙動の説明
  - 公開 API の引数、戻り値、呼び出す前に満たす条件を定義する doc コメント
  - コードで表せない制約を説明する issue や RFC へのリンク
  - フォーマッタの指示（`prettier-ignore` など）
  - lint や型チェックの抑制のうち、ルールが誤っている、細かすぎる、スタイルだけを見ているもの

## 指摘の書き方

レビューや採点で観点に当たるものを挙げるときは、次を書く。

- 場所（`file:line`）
- 観点の番号
- 消すもの、または置き換えるもの
- 置き換えた後の形（数行）
- 根拠
